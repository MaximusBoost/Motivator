# Локальная проверка GigaChat

Тест обращается к реальному GigaChat API, поэтому расходует токены проекта. Он
проверяет OAuth, список доступных моделей, обычную генерацию и принудительный
вызов пользовательской функции с результатом проверки учебного ответа.

Создайте игнорируемый Git файл `.env.ai.local` в корне проекта:

```text
GIGACHAT_CREDENTIALS=<Authorization Key из кабинета GigaChat API>
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_BASE_URL=https://api.giga.chat/v1
```

Не используйте префикс `VITE_`: ключ предназначен только для серверного кода.
Запуск:

```powershell
npm run smoke:gigachat
```

Для личной проверки в интерфейсе запустите приложение обычной командой:

```powershell
npm run dev
```

В локальном mock-режиме отправка развёрнутого ответа вызывает серверный адрес
`/api/ai/review-free-answer`. Сервер самостоятельно находит теорию, закрытые
опорные пункты и критерии по `activityId`; браузер передаёт только текст ответа.
Каждая отправка выполняет реальный запрос и расходует токены проекта GigaChat.

Тест не печатает Authorization Key и временный access token. Он выбирает
подходящую модель из ответа `/models`. Для явного выбора добавьте в локальный
env-файл `GIGACHAT_MODEL=<идентификатор модели>`.

Публичный корневой сертификат НУЦ Минцифры из официального источника сохранён в
`certs/russian_trusted_root_ca_pem.crt`. Smoke-команда автоматически
перезапускает Node с этим сертификатом, не меняя системное хранилище Windows.
Если нужно проверить другой актуальный сертификат, передайте путь явно:

```powershell
$env:NODE_EXTRA_CA_CERTS = "C:\полный\путь\к\russian_trusted_root_ca_pem.crt"
npm run smoke:gigachat
```

Не отключайте проверку TLS через `NODE_TLS_REJECT_UNAUTHORIZED=0` или
`rejectUnauthorized: false`: такой режим допустим только как чужой учебный
пример, но не для приложения и не для проверки настоящего ключа.
