# Серверные AI-функции

`supabase/functions/review-free-answer` запускается после сохранения свободного
ответа. Браузер передаёт только `attemptId`; функция сама проверяет JWT и
владельца попытки, загружает ответ, теорию модуля, закрытые опорные пункты и
критерии через service role, вызывает AI и валидирует результат перед записью в
PostgreSQL.

## Провайдер и секреты Edge Function

```text
OPENAI_API_KEY=server-only-project-key
OPENAI_MODEL=gpt-5.6-terra
OPENAI_BASE_URL=https://api.openai.com/v1
OPENAI_TIMEOUT_MS=45000
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляет окружение Supabase.
Ни один из этих секретов нельзя добавлять в `.env.local` Vite или переменные с
префиксом `VITE_`.

Обе функции используют общий адаптер
`supabase/functions/_shared/openai.ts`. Он вызывает Responses API с
`store: false`, передаёт вместо `user.id` его SHA-256-псевдоним и требует
Structured Outputs по строгой JSON Schema. Модель можно заменить через
`OPENAI_MODEL`; frontend, таблицы и репозиторий от модели не зависят.

## Проверка свободного ответа

Функция отправляет модели текст ответа, `referenceMaterial`,
`referenceAnswerPoints`, критериями и ожидаемой схемой. Опорные пункты хранятся
в `free_answer_rubrics`, недоступной браузерным ролям. Детальные поля критериев
тоже доступны только `service_role`; frontend получает названия и веса.

Ответ пользователя считается недоверенными данными. Провайдеру явно указано
игнорировать инструкции внутри ответа, не добавлять отсутствующие в материале
факты, не ставить диагнозы и не восстанавливать служебные сведения. Адаптер
провайдера должен вернуть JSON:

Перед отправкой пользователь отдельно подтверждает, что ответ не содержит
подразделение, место службы, ВУС, реальные координаты, персональные данные и
иные служебные сведения. Это обязательная продуктовая граница, но не замена
организационным правилам обращения с информацией.

```json
{
  "criterionScores": [
    { "criterionId": "uuid", "score": 82, "feedback": "Краткий комментарий" }
  ],
  "strength": "Что получилось",
  "improvement": "Что исправить",
  "recommendation": "Что повторить"
}
```

Для каждого переданного критерия обязателен балл 0–100. Лишние или пропущенные
поля, дубли критериев, выход балла за диапазон, отказ модели и незавершённый
ответ отклоняются. Итоговый балл считается самой Edge Function с учётом весов
из БД, а не принимается от модели.

До настройки ключа функция отвечает 503, а пользовательский ответ остаётся
сохранённым в статусе `submitted`. При временной ошибке статус возвращается из
`reviewing` в `submitted`, и пользователь может повторить проверку. Экран
результата автоматически опрашивает сервер около 30 секунд. Локальный mock
выполняет только явно обозначенную алгоритмическую оценку — это не AI.

## Совет по физической подготовке

`supabase/functions/advise-physical-training` получает `resultId`, проверяет
владельца и загружает до пяти последних физических результатов. Заметки и
служебный профиль провайдеру не отправляются. Задача имеет имя
`advise_physical_training`, ответ:

```json
{
  "summary": "Краткий разбор динамики",
  "recommendations": ["Безопасный следующий шаг", "Второй шаг"],
  "caution": "Ограничения рекомендации и когда нужен специалист"
}
```

Функция не отправляет заметки пользователя и обобщённый служебный профиль. Она
запрещает медицинские диагнозы, экстремальные нагрузки, действия через боль и
запрос служебных сведений. Результат сохраняется в
`physical_training_advice`; это учебная рекомендация, а не официальный или
медицинский план.

Страница практики ожидает результат около 30 секунд и позволяет повторно
запросить рекомендацию. Повторный вызов идемпотентен: если совет для результата
уже создан, Edge Function возвращает существующую запись.

## Локальная настройка

Скопируйте `supabase/functions/.env.example` в игнорируемый файл
`supabase/functions/.env.local`, добавьте ключ и запустите функции:

```powershell
npm run supabase:functions
npm run smoke:ai-provider
```

Smoke-тест не обращается к OpenAI и не расходует средства: HTTP-ответ
подменяется локально, при этом проверяются тело Responses API, строгая схема,
псевдоним пользователя, разбор JSON и отказ модели.

## Деплой

```powershell
supabase functions deploy review-free-answer
supabase functions deploy advise-physical-training
supabase secrets set OPENAI_API_KEY=... OPENAI_MODEL=gpt-5.6-terra
```

Если позже потребуется другой провайдер, заменяется общий серверный адаптер;
контракты функций, React-компоненты и структура базы остаются прежними.
