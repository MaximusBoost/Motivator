# Серверные AI-функции

`supabase/functions/review-free-answer` запускается после сохранения свободного
ответа. Браузер передаёт только `attemptId`; функция сама проверяет JWT и
владельца попытки, загружает ответ, теорию модуля, закрытые опорные пункты и
критерии через service role, вызывает AI и валидирует результат перед записью в
PostgreSQL.

## Секреты Edge Function

```text
AI_PROVIDER_URL=https://your-server-adapter.example/task
AI_PROVIDER_API_KEY=server-only-secret
```

`SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` предоставляет окружение Supabase.
Ни один из этих секретов нельзя добавлять в `.env.local` Vite или переменные с
префиксом `VITE_`.

## Проверка свободного ответа

Функция отправляет POST с задачей, текстом ответа, `referenceMaterial`,
`referenceAnswerPoints`, критериями и ожидаемой схемой. Опорные пункты хранятся
в `free_answer_rubrics`, недоступной браузерным ролям. Детальные поля критериев
тоже доступны только `service_role`; frontend получает названия и веса.

Ответ пользователя считается недоверенными данными. Провайдеру явно указано
игнорировать инструкции внутри ответа, не добавлять отсутствующие в материале
факты, не ставить диагнозы и не восстанавливать служебные сведения. Адаптер
провайдера должен вернуть JSON:

```json
{
  "criterionScores": [
    { "criterionId": "uuid", "score": 82, "feedback": "Краткий комментарий" }
  ],
  "strength": "Что получилось",
  "improvement": "Что исправить",
  "recommendation": "Что повторить"
}
```

Для каждого переданного критерия обязателен балл 0–100. Лишние или пропущенные
поля, выход балла за диапазон и не-JSON ответ отклоняются. Итоговый балл
считается самой Edge Function с учётом весов из БД.

До настройки провайдера функция отвечает 503, а пользовательский ответ остаётся
сохранённым в статусе `submitted`. Локальный mock выполняет только явно
обозначенную алгоритмическую оценку — это не AI.

## Совет по физической подготовке

`supabase/functions/advise-physical-training` получает `resultId`, проверяет
владельца и загружает до пяти последних физических результатов. Заметки и
служебный профиль провайдеру не отправляются. Задача имеет имя
`advise_physical_training`, ответ:

```json
{
  "summary": "Краткий разбор динамики",
  "recommendations": ["Безопасный следующий шаг", "Второй шаг"],
  "caution": "Ограничения рекомендации и когда нужен специалист"
}
```

Функция запрещает медицинские диагнозы, экстремальные нагрузки, действия через
боль и запрос служебных сведений. Результат сохраняется в
`physical_training_advice`; это учебная рекомендация, а не официальный или
медицинский план.

## Деплой

```powershell
supabase functions deploy review-free-answer
supabase functions deploy advise-physical-training
supabase secrets set AI_PROVIDER_URL=... AI_PROVIDER_API_KEY=...
```

Выбор конкретного AI-провайдера намеренно отложен: frontend и база от него не
зависят, потребуется только небольшой серверный адаптер к этому контракту.
