КАРТА ДАННЫХ MOTIVATOR
======================

Этот файл объясняет, какие данные уже есть в проекте и как они связаны
с блоками интерфейса из Figma.


1. ОТКУДА БЕРУТСЯ ДАННЫЕ
------------------------

Импорт в компонентах и страницах всегда один:

import { learningRepository } from "~/data/learning";

Если в .env.local НЕТ VITE_SUPABASE_URL и VITE_SUPABASE_PUBLISHABLE_KEY,
learningRepository читает локальные данные из:

app/data/repositories/mock-learning.repository.ts

Если ключи Supabase добавлены, learningRepository переключается на:

app/data/repositories/supabase-learning.repository.ts

Компонентам при этом не нужно знать, откуда пришли данные.


2. САМОЕ ВАЖНОЕ: ТЕКУЩИЙ МОДУЛЬ И СЛЕДУЮЩЕЕ ЗАДАНИЕ
--------------------------------------------------

Не нужно искать их вручную внутри subjects. Для карточки
«Продолжить обучение» получай dashboard:

const dashboard = await learningRepository.getDashboard();
const current = dashboard.continueLearning;

current может быть null, если пользователь еще ничего не начинал.

if (current) {
  console.log(current.subjectTitle);       // Медицинская подготовка
  console.log(current.moduleNumber);       // 4
  console.log(current.modulesTotal);       // 8
  console.log(current.moduleTitle);        // Первая помощь (подпись в макете)
  console.log(current.nextActivityTitle);  // Тест: первичная оценка состояния
  console.log(current.progressPercent);    // 62
}

Если нужен не короткий текст карточки, а полный объект текущего модуля:

const currentModule = current
  ? await learningRepository.getModule(current.moduleId)
  : null;

console.log(currentModule?.title);
// Оценка ситуации и принятие решений

То есть "Первая помощь" сейчас является подписью в компактной карточке Figma,
а "Оценка ситуации и принятие решений" — полным названием medical-m4.

Все поля continueLearning:

dashboard.continueLearning.subjectId
  ID текущего предмета: "medical".

dashboard.continueLearning.subjectTitle
  Заголовок карточки: "Медицинская подготовка".

dashboard.continueLearning.subjectCode
  Короткая подпись/иконка предмета: "М".

dashboard.continueLearning.moduleId
  ID текущего модуля: "medical-m4".

dashboard.continueLearning.moduleNumber
  Номер текущего модуля: 4.

dashboard.continueLearning.modulesTotal
  Всего модулей в предмете: 8.

dashboard.continueLearning.moduleTitle
  Текст модуля для карточки продолжения: "Первая помощь".

dashboard.continueLearning.nextActivityId
  ID следующего задания: "medical-m4-quiz".
  Этот ID нужно использовать для открытия страницы теста.

dashboard.continueLearning.nextActivityTitle
  Текст следующего задания: "Тест: первичная оценка состояния".

dashboard.continueLearning.progressPercent
  Процент для progress bar: 62.

ВАЖНО:
getSubjects() показывает структуру каталога и статусы всех предметов.
getDashboard().continueLearning явно говорит, какой ОДИН модуль сейчас нужно
показывать пользователю как основной и какое задание открыть следующим.

const subjects = await learningRepository.getSubjects();

subjects — массив из 7 предметов:

subjects[0] — Медицинская подготовка, 8 модулей, прогресс 62%, балл 82.
subjects[1] — Огневая подготовка, 6 модулей, прогресс 44%, балл 71.
subjects[2] — РХБ защита, 5 модулей, прогресс 81%, балл 88.
subjects[3] — Тактическая подготовка, 7 модулей, прогресс 33%, балл 64.
subjects[4] — Военная топография, 7 модулей, прогресс 26%, балл 59.
subjects[5] — Инженерная подготовка, 4 модуля, прогресс 0%, балла еще нет.
subjects[6] — Общевоинские уставы, 5 модулей, прогресс 91%, балл 93.

по id или slug:

const currentModule = medical?.modules.find(

4. ПОЛЯ ПРЕДМЕТА И КАРТОЧКА В КАТАЛОГЕ
---------------------------------------

Каждый subject имеет следующую структуру:

subject.id
  Внутренний ID. В mock это "medical", "firearms", "rhb" и т.д.

subject.code
  Номер на карточке: "01", "02", ... "07".

subject.slug
  Человекочитаемая часть URL, например "medical-training".
  Подходит для маршрута /subjects/medical-training.

subject.title
  Название карточки: "Медицинская подготовка".

subject.subtitle
  Подпись карточки: "Первая помощь • алгоритмы".

subject.theme
  Цветовой вариант карточки: "blue" или "olive".
  Его удобно передавать в clsx:

  className={clsx(styles.card, styles[subject.theme])}

subject.position
  Порядок предмета в каталоге.

subject.estimatedMinutes
  Примерная общая длительность предмета в минутах.

subject.modules
  Массив модулей этого предмета.

subject.status
  "not_started" — не начат;
  "in_progress" — в процессе;
  "completed" — завершен.

subject.progressPercent
  Число от 0 до 100 для progress bar.

subject.lastScore
  Последний балл пользователя или null, если результатов еще нет.

Для карточки предмета из Figma нужны главным образом:

subject.code
subject.title
subject.subtitle
subject.modules.length
subject.progressPercent
subject.status
subject.theme


5. МОДУЛИ ВНУТРИ ПРЕДМЕТА
--------------------------

const medical = await learningRepository.getSubjectBySlug(
  "medical-training",
);

const modules = medical?.modules ?? [];

Текущий медицинский модуль:

const module = medical?.modules.find(
  (item) => item.id === "medical-m4",
);

В mock это четвертый модуль:

ID:                 medical-m4
number:             4
title:              Оценка ситуации и принятие решений
summary:            Тест + свободный ответ
status:             in_progress
progressPercent:    58
estimatedMinutes:   47

Поля module:

module.id
  ID модуля. Он связывает модуль с activities и используется в маршруте.

module.subjectId
  ID родительского предмета.

module.number
  Порядковый номер модуля.

module.title
  Полное название модуля для страницы программы предмета.

module.summary
  Короткая подпись: "Теория + тест", "Тест" и т.д.

module.estimatedMinutes
  Время прохождения в минутах или null.

module.objective
  Цель модуля для теоретической страницы.

module.keyPrinciple
  Выделенный ключевой принцип.

module.shortSummary
  Краткое резюме материала.

module.learningTip
  Совет учащемуся.

module.sections
  Разделы теории. У каждого есть id, title, body и position.

module.activities
  Теория, тесты и свободные ответы внутри модуля.

module.status и module.progressPercent
  Состояние модуля и процент для его progress bar.

Если тебе нужно найти любой модуль сразу по ID:

const module = await learningRepository.getModule("medical-m4");


6. ACTIVITIES — ЗАДАНИЯ ВНУТРИ МОДУЛЯ
-------------------------------------

module.activities содержит разные виды учебной активности.

activity.type === "theory"
  Теоретическая часть.

activity.type === "quiz"
  Тест с вопросами и вариантами ответов.

activity.type === "free_answer"
  Задание с развернутым ответом и критериями оценки.

Общие поля любой activity:

activity.id
activity.moduleId
activity.type
activity.title
activity.description
activity.position
activity.estimatedMinutes

У текущего medical-m4 массив activities выглядит так:

activities[0]
  id: medical-m4-theory
  type: theory
  title: Теория

activities[1]
  id: medical-m4-quiz
  type: quiz
  title: Проверка знаний
  Это следующее задание из dashboard.continueLearning.nextActivityId.

activities[2]
  id: medical-m4-free-answer-1
  type: free_answer
  title: Развернутый ответ

activities[3]
  id: medical-m4-free-answer-2
  type: free_answer
  title: Практический сценарий

Чтобы получить следующее задание полностью:

const dashboard = await learningRepository.getDashboard();
const nextActivityId = dashboard.continueLearning?.nextActivityId;

const nextActivity = nextActivityId
  ? subjects
      .flatMap((subject) => subject.modules)
      .flatMap((module) => module.activities)
      .find((activity) => activity.id === nextActivityId)
  : null;

Для теста еще удобнее вызвать специальный метод:

const quiz = nextActivityId
  ? await learningRepository.getQuiz(nextActivityId)
  : null;


7. СТРАНИЦА ТЕОРИИ
------------------

Для страницы теории получи весь модуль:

const module = await learningRepository.getModule("medical-m4");

В интерфейс выводятся:

Заголовок страницы              -> module.title
Цель модуля                     -> module.objective
Ключевой принцип                -> module.keyPrinciple
Основной текст                  -> module.sections
Краткое резюме                  -> module.shortSummary
Совет                           -> module.learningTip
Время                           -> activity.estimatedMinutes
Прогресс                        -> module.progressPercent

Пример вывода разделов:

module?.sections.map((section) => (
  <section key={section.id}>
    <h2>{section.title}</h2>
    <p>{section.body}</p>
  </section>
));


8. СТРАНИЦА ТЕСТА
-----------------

const quiz = await learningRepository.getQuiz("medical-m4-quiz");

Поля теста:

quiz.title
  Заголовок теста.

quiz.description
  Подпись теста.

quiz.estimatedMinutes
  Примерное время.

quiz.questions
  Массив вопросов. У текущего подробного теста 10 вопросов.

Поля вопроса:

question.id
question.prompt          — текст вопроса;
question.instructions    — инструкция «Выберите один вариант»;
question.hint            — подсказка или null;
question.position        — номер вопроса;
question.options         — варианты ответа.

Поля варианта ответа:

option.id
option.label             — A, B, C, D;
option.text              — текст варианта.

Правильного ответа во фронтенд-объекте НЕТ специально. Пользователь не должен
получать ключи теста в браузер. Позднее отправляем выбранный option.id на бэкенд,
а оценивание выполняет сервер или Supabase Edge Function.

12. КАК НАЙТИ ТЕКУЩИЙ МОДУЛЬ ТОЛЬКО ЧЕРЕЗ subjects
--------------------------------------------------

Иногда это полезно, но для главной страницы проще использовать continueLearning.

const currentSubject = subjects.find((subject) =>
  subject.modules.some((module) => module.status === "in_progress"),
);

const currentModule = currentSubject?.modules.find(
  (module) => module.status === "in_progress",
);

const firstUnfinishedActivity = currentModule?.activities.find(
  (activity) => {
    // Сейчас activity не содержит собственный status в интерфейсной модели.
    // Поэтому надежный nextActivity уже подготовлен в dashboard.continueLearning.
    return activity.id === dashboard.continueLearning?.nextActivityId;
  },
);

Почему не стоит просто брать activities[1]: порядок может измениться, а в
другом модуле вторым элементом может быть не тот экран, который нужен конкретному
пользователю. nextActivityId — более надежная связь.


13. ВАЖНО ПРИ ПОДКЛЮЧЕНИИ НАСТОЯЩЕГО ПОЛЬЗОВАТЕЛЯ
-------------------------------------------------

Mock хранит состояние одного демонстрационного пользователя и игнорирует userId.
Поэтому сейчас можно вызывать методы без аргумента.

Supabase хранит личный прогресс отдельно. После авторизации нужно вызывать:

const subjects = await learningRepository.getSubjects(user.id);
const dashboard = await learningRepository.getDashboard(user.id);
const results = await learningRepository.getResults(user.id);

Без user.id Supabase вернет общий учебный каталог, но личный прогресс будет
нулевым, continueLearning будет null, а персональный план — пустым.


14. КАК ЗАГРУЖАТЬ ДАННЫЕ В СТРАНИЦЕ REACT ROUTER
------------------------------------------------

Лучше не выполнять await на верхнем уровне файла компонента. Используй
clientLoader страницы:

export async function clientLoader() {
  const [dashboard, subjects] = await Promise.all([
    learningRepository.getDashboard(),
    learningRepository.getSubjects(),
  ]);

  return { dashboard, subjects };
}

export default function Home({ loaderData }: Route.ComponentProps) {
  const { dashboard, subjects } = loaderData;

  return <main>{/* твоя верстка */}</main>;
}

16. ЧТО ДОБАВЛЕНО В MVP 16.08.2026
---------------------------------

Все персональные методы теперь получают user.id:

const userId = await getCurrentUserId();
const dashboard = await learningRepository.getDashboard(userId);

Новые действия репозитория:

await learningRepository.submitQuiz(activityId, answers, userId);
await learningRepository.submitFreeAnswer(activityId, answer, userId);
await learningRepository.completeTheory(activityId, userId);
await learningRepository.setTodayPlanItemCompleted(itemId, true, userId);
await learningRepository.getGoals(userId);
await learningRepository.setGoal(subjectId, 5, userId);

В mock-режиме персональное состояние хранится в localStorage под ключом
motivator:learning:<userId>. Оно нужно только для разработки без Supabase.

В Supabase-режиме:

- auth.users хранит email и пароль средствами Supabase Auth;
- profiles хранит уникальный никнейм;
- user_activity_progress хранит прогресс активностей;
- activity_attempts и quiz_answers хранят попытки и ответы;
- user_subject_goals хранит целевые оценки;
- daily_plan_items хранит личный план на день;
- submit_quiz(...) проверяет тест на стороне PostgreSQL, поэтому правильные
  ответы не попадают в браузер.

Свободный ответ в Supabase после отправки получает статус submitted. Балл и
AI-комментарий появятся после подключения серверной Edge Function. Локальный
mock показывает только явно подписанную предварительную алгоритмическую оценку,
чтобы не выдавать ее за настоящий AI-анализ.


17. ПЕРСОНАЛЬНЫЙ МАРШРУТ К КЛАССНОСТИ (17.08.2026)
--------------------------------------------------

Служебный профиль и цель:

const profile = await learningRepository.getQualificationProfile(userId);

await learningRepository.saveQualificationProfile({
  isActiveServiceMember: true,
  serviceType: "contract",
  personnelCategory: "soldier",
  positionProfile: "specialist",
  hasSubordinates: false,
  serviceDirection: "general",
  serviceStartedAt: "2025-08-17",
  currentQualification: "none",
  qualificationAwardedAt: null,
  qualificationExpiresAt: null,
  targetQualification: "third",
}, userId);

Готовый объект для dashboard и страницы «Мой маршрут»:

const roadmap = await learningRepository.getQualificationRoadmap(userId);

roadmap.profile                    — служебный профиль или null;
roadmap.readinessPercent          — общая учебная готовность 0–100;
roadmap.learningReadinessPercent  — теория и обычные тесты;
roadmap.practiceReadinessPercent  — внесённая практика;
roadmap.examReadinessPercent      — последнее пробное испытание;
roadmap.physicalGrade             — последняя самостоятельная оценка физподготовки;
roadmap.predictedQualification    — предварительный прогноз;
roadmap.blockers                  — что мешает цели;
roadmap.requirements              — карточки этапов с href и прогрессом;
roadmap.subjects                  — готовность по каждому предмету.

У roadmap.subjects есть preparationPriority: "core", "profile" или
"additional". Это только учебная сортировка приложения: базовое ядро + акцент
по обобщённому направлению. Она не заменяет перечень предметов, определённый
уполномоченным должностным лицом.

Пробное испытание:

const exam = await learningRepository.createQualificationExam(
  [subjectId1, subjectId2, subjectId3, subjectId4],
  userId,
);

В exam по 10 вопросов на выбранный предмет, подсказки удалены. После заполнения
объекта answers, где ключ — question.id, значение — option.id:

const result = await learningRepository.submitQualificationExam(
  exam,
  answers,
  userId,
);

В Supabase правильные ответы проверяет submit_qualification_exam(...), а не
браузер. result.predictedQualification — только тренировочный прогноз.

Практика и физподготовка:

const results = await learningRepository.getPracticeResults(userId);

await learningRepository.savePracticeResult({
  category: "physical",       // либо "professional"
  subjectId: null,
  title: "Бег 3 км",
  value: 12.4,
  unit: "мин",
  grade: 4,
  performedAt: "2026-08-17",
  notes: null,
}, userId);

Все такие результаты имеют source: "self_reported". Они не являются
официальной ведомостью. В MVP не хранятся номер части, ВУС, точная должность,
место службы и сведения ограниченного распространения.

Новые страницы:
